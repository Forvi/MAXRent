# Анализ проекта: бот безопасного заключения договора аренды жилья в MAX

---

# ЭТАП 1. ОЗНАКОМЛЕНИЕ И РАЗБОР ОПИСАНИЯ

## 1.1. Ключевая идея продукта

**Продукт:** чат-бот в мессенджере MAX — «цифровой помощник по оформлению сделки аренды жилья»: пошаговая анкета для обеих сторон, проверка полноты данных, автоматическая генерация договора и акта приёма-передачи в удобном формате (PDF).

**Какую проблему решает** (из описания):
- стороны частной аренды оформляют сделку устно или по случайным шаблонам из интернета;
- в документах не фиксируются: размер и порядок оплаты, залог, коммунальные платежи, состояние имущества, ответственность сторон и порядок расторжения;
- стороны не различают договор найма жилого помещения и договор аренды недвижимости → по-разному трактуют права и обязанности → споры, финансовые потери, слабая позиция при защите интересов.

**Для кого:** участники частного рынка аренды жилья — собственники (арендодатели) и арендаторы, преимущественно физические лица.

**Сценарий использования внутри MAX:**
стороны уже нашли друг друга (объявление на Авито/ЦИАН, знакомые, чаты домов) → открывают бота в MAX → бот определяет роли и статус сторон (физлицо/ИП/юрлицо) → ведёт обоих по пошаговой анкете (объект, срок, плата, залог, коммунальные платежи, опись имущества, условия расторжения) → проверяет полноту и предупреждает о пробелах → формирует договор + акт приёма-передачи → отдаёт PDF в чат, фиксирует согласие сторон.

**Ценность:** корректный юридический документ за 10–15 минут, не выходя из мессенджера, дёшево или бесплатно; снижение риска споров.

## 1.2. Ограничения платформы MAX

По официальной документации платформы (dev.max.ru) и по описанию проекта:

1. **Публикация бота** требует подключения к платформе «MAX для партнёров», создания и верификации профиля организации, ИП или самозанятого — резидента РФ; бот проходит модерацию. Без верифицированного профиля бот нельзя опубликовать (можно только разрабатывать и тестировать локально).
2. **Bot API** — HTTPS REST-интерфейс (эндпоинты вида `platform_api.max.ru`: `/me`, `/messages`, подписка на события через webhook-подписки). Бот умеет: отправлять/принимать сообщения, обрабатывать нажатия кнопок (колбэки), получать данные о пользователе в рамках, предоставляемых API.
3. **Мини-приложения** доступны (веб-технологии HTML/JS/CSS + библиотека MAX Bridge + React-компоненты MAX UI) — вариант для длинной анкеты или просмотра договора, если чат-формат тесен.
4. **Цифровой ID** (подтверждение личности/статусов) — подключение только для юрлиц и ИП. В описании проекта не заявлен → в MVP не рассчитывать.
5. **Интеграция с Госуслугами** в описании упомянута как направление развития («Госуслуги имеют оформление договоров найма, включая удалённое взаимодействие сторон»). Публичного API Госуслуг для сторонних ботов в описании нет; существующий государственный сценарий — онлайн-подписание договора найма в связке ЦИАН × Госуслуги. Для MVP считать недоступной, заложить в roadmap.
6. Из описания следует обязательный функционал: работа с текстом (анкета), проверка полноты, генерация документов «в удобном формате» (PDF). OCR и выгрузка из Госуслуг упомянуты в задачах как «доступный метод» работы с документами — в MVP реалистичный метод: ручной ввод через анкету + загрузка фото документов (OCR — бонус).

## 1.3. Глоссарий проекта

| Термин | Значение |
|---|---|
| Договор найма жилого помещения | Гл. 35 ГК РФ (ст. 671–688). Заключается, когда обе стороны — физические лица. Основной вид для частной аренды жилья |
| Договор аренды | Гл. 34 ГК РФ (ст. 606–625). Арендатор — юрлицо/ИП; жильё может использоваться только для проживания граждан (п. 2 ст. 671 ГК РФ) |
| Наймодатель / наниматель | Стороны договора найма (аналог: арендодатель / арендатор) |
| Краткосрочный / долгосрочный найм | До 1 года / от 1 года до 5 лет (ст. 683 ГК РФ) |
| Обеспечительный платёж (залог) | Ст. 381.1 ГК РФ — денежное обеспечение обязательств, возвращается за вычетом долгов/ущерба |
| Акт приёма-передачи + опись имущества | Документ, фиксирующий состояние помещения и имущества, показания счётчиков при передаче |
| Госрегистрация обременения | Найм на срок ≥ 1 года — регистрация ограничения права собственности (п. 2 ст. 674 ГК РФ) |
| ПЭП / НЭП / КЭП | Простая / неквалифицированная / квалифицированная электронная подпись (ФЗ № 63-ФЗ) |
| Платформа «MAX для партнёров» | Кабинет для создания ботов, мини-приложений и каналов в MAX |
| MAX Bot API | REST-интерфейс взаимодействия бота с платформой MAX |
| MAX Bridge | Библиотека-посредник для обмена данными мини-приложения с MAX |
| Цифровой ID | Цифровой аналог документов для подтверждения личности/статусов в MAX (доступен юрлицам и ИП) |
| ER-диаграмма | Схема сущностей и связей базы данных |

**Вывод по Этапу 1:**
1. Продукт — конструктор и «проверяльщик» договора найма/аренды в чате MAX; ядро ЦА — физлица-участники частной аренды.
2. Ключевая юридическая развилка, которую бот обязан закрывать (прямо из описания): найм (физлица) vs аренда (юрлицо/ИП) — определение вида договора по статусу сторон.
3. Жёсткое платформенное ограничение: публикация бота требует верифицированного профиля юрлица/ИП/самозанятого РФ и модерации; API — REST + webhooks; Цифровой ID в MVP недоступен.
4. Интеграция с Госуслугами — стратегическая цель (roadmap), не факт MVP: публичного API для сторонних ботов нет.
5. Открытый вопрос (критический): наличие у команды верифицированного профиля на платформе MAX для партнёров — см. конец документа.

## 2.5. Стратегия демо при отсутствии верифицированного профиля MAX (решение)

**Факт:** у команды нет верифицированного профиля на платформе «MAX для партнёров» → опубликовать бота нельзя.

**Решение — «эмулятор вместо публикации»:**
1. Контроллер бота пишется против контракта MAX Bot API (REST + webhook-события) как есть — без костылей под демо.
2. Пишется локальный эмулятор MAX: веб-консоль с двумя окнами-«пользователями», которая шлёт те же webhook-события и рисует ответы бота. Для backend это неотличимо от продакшена.
3. Демо: два окна эмулятора = две стороны сделки, проходят анкету, получают PDF. Записывается видео.
4. На защите честно проговаривается: публикация требует верифицированного профиля юрлица/ИП/самозанятого РФ и модерации — это ограничение платформы, а не продукта; код готов к подключению токена реального бота (замена URL эмулятора на platform-api.max.ru + токен).
5. Параллельно (хедж): подать заявку на верификацию профиля немедленно — процесс небыстрый; если успеет пройти до защиты, показать живого бота.

**Что НЕ делать:** не пытаться обойти модерацию, не показывать «скриншоты якобы живого бота» — жюри проверяет, обман дороже честного эмулятора.

**Вывод по Этапу 2:**
1. Задачи распадаются на 4 группы: аналитика (8), юр. блок (3), ядро разработки (4), инженерная зрелость (4).
2. Критический путь проходит через юр. блок: шаблон договора определяет поля анкеты, БД, API и PDF.
3. Аналитическая цепочка тоже последовательна: ЦА/опрос → конкуренты → монетизация → окупаемость → графики → README.
4. Разработка заявлена организаторами «позже» — значит на защите ценится связка «аналитика + юр. корректность + работающее демо ядра».
5. Соц. опрос — единственная задача, требующая внешних данных; запускать сразу (долго собирается).

# ЭТАП 4. ДЕТАЛЬНАЯ АНАЛИТИКА

(Этап 3 — юридический блок — см. `шаблон_договора_найма.md`; ниже аналитика.)

## 4.1. Целевая аудитория

**С1. Собственники-физлица, сдающие 1–2 объекта**
- Кто: 30–60 лет, сдают квартиру «по случаю» (наследство, переезд, инвестиция).
- Потребности: быстро и надёжно оформить сделку; зафиксировать состояние имущества и залог; защититься от неоплаты и порчи.
- Боли: не знают, какие условия обязательно включить; путают найм и аренду; боятся «хитрых» жильцов; юрист стоит 2–5 тыс. ₽ и требует времени.
- Триггеры в MAX: нашли жильца (Авито, сарафан) и нужно оформление «сегодня»; рекомендация в чатах ЖК/района.
- Частота: 1–3 сделки в год, эпизодически → продукт разового действия + напоминания о продлении/платежах.

**С2. Арендаторы-физлица (25–40 лет, крупные города)**
- Потребности: защитить залог (главный страх — «не вернут»); зафиксировать состояние квартиры на входе; иметь подтверждение оплаты; договор для регистрации по месту пребывания, требований банка/работодателя.
- Боли: собственник предлагает «по-простому, на словах» или шаблон из интернета с кабальными пунктами; нет акта → при выезде спор о состоянии и залоге.
- Триггеры: переезд, съём впервые; требование формальностей от третьих лиц.
- Частота: 1–2 переезда в 2–3 года.

**С3. Профессиональные арендодатели и агенты (2–20+ объектов)**
- Потребности: стандартизация документов; скорость оформления; архив сделок; шаблоны под разные ситуации (меблированная/пустая, краткосрок/долгосрок).
- Боли: каждый договор собирается заново; ошибки в самодельных шаблонах; бумаги теряются.
- Триггеры: поток сделок; потребность в единообразии.
- Частота: еженедельно → главный кандидат на подписку.

Роль «администратор» (для B2B-тарифа с командой) — в MVP не выделяется, появляется с подпиской Pro.

Гипотезы для проверки соц. опросом (A3): как оформляли прошлую сделку (устно/шаблон/юрист/сервис); были ли споры из-за неполного договора; что мешало оформить правильно; готовность платить и сколько; знают ли разницу найм/аренда.

## 4.2. Анализ конкурентов

**Прямые:**

| Конкурент | Что делает | Сильное | Слабое для нашего пользователя |
|---|---|---|---|
| Госуслуги × ЦИАН («Подписать договор онлайн») | Дистанционное заключение договора найма с ПЭП, проверка условий сервисом | Государственный статус, бесплатно, легальность | Работает внутри сделок ЦИАН; не помогает парам, нашедшим друг друга вне площадки; нет пошаговой анкеты «с нуля» и описи имущества |
| Яндекс Аренда | Полный сервис долгосрочной аренды: договор юристов сервиса, ПЭП, финзащита, проверка жильцов через Госуслуги | Полный цикл, доверие к бренду, юридическая проработка | Это посредник со своей комиссией и правилами, а не инструмент для самостоятельных сторон; работает только со «своими» сделками |
| Конструкторы документов (Doczilla, FreshDoc и др.) | Онлайн-конструкторы любых договоров, включая найм | Гибкость, юридическая аккуратность | Веб-инструменты «для одного человека»; нет сценария «две стороны в одном диалоге»; ориентир на бизнес/юристов |
| Боты шаблонов договоров в Telegram/VK | Выдача шаблона по команде | Формат мессенджера | Обычно просто отдают файл; нет анкеты, проверки полноты, акта, ветки найм/аренда |

**Косвенные:**
- Площадки (Авито Недвижимость, Домклик, ЦИАН) — помогают найти друг друга, но не оформляют сделку.
- «Случайный шаблон из интернета» — фактический главный конкурент: бесплатно и мгновенно, но именно его неполнота и порождает проблему из описания проекта.
- Юрист/риелтор — качественно, но 2–10 тыс. ₽ и дни ожидания.

**Конкурентные преимущества разрабатываемого продукта:**
1. Сделка целиком в MAX: обе стороны в одном сценарии, без выхода в веб и без посредника между ними.
2. Не «шаблон», а «ведение за руку»: пошаговая анкета с проверкой полноты и подсказками (что и зачем фиксируем).
3. Автоматический выбор корректного вида договора (найм vs аренда) по статусу сторон — закрывает боль из описания.
4. Пакет документов: договор + акт приёма-передачи с описью имущества и показаниями счётчиков.
5. Цена существенно ниже юриста; базовый сценарий — бесплатно.
6. Задел на интеграцию с Госуслугами/госсценариями (описание прямо позиционирует это как развитие).

## 4.3. Монетизация

**M1. Подписка**
- Механика в MAX: базовый пакет бесплатно (простой договор + акт, 1 сделка/мес); Pro за 199 ₽/мес или 1 490 ₽/год: неограниченные сделки, свои шаблоны/логотип, архив и история, напоминания о платежах и продлении, приоритетная поддержка; командный тариф для агентов.
- Плюсы: предсказуемый доход; масштабируется с профессиональным сегментом (С3); не мешает массовой бесплатной базе.
- Минусы: массовые сегменты С1/С2 платят редко (потребность разовая) → низкая конверсия; подписку нужно постоянно оправдывать ценностью.
- Применимость: высокая для С3, низкая для С1/С2.

**M2. Процент со сделки**
- Механика: бот сопровождает первый платёж/залог (платёжный сценарий в MAX при доступности либо партнёрский эквайринг) и удерживает фикс или 0,5–1%.
- Плюсы: растёт с ценой сделки; для пользователя психологически «бесплатно».
- Минусы: нужна платёжная инфраструктура и юр. чистота (54-ФЗ, агентские схемы, риск вопросов при удержании чужих денег); стороны часто платят напрямую — обход; конфликт доверия: «помощник» превращается в посредника по деньгам.
- Применимость: среднесрочно, после накопления доверия; в MVP — нет.

**M3. Реклама / партнёрские размещения**
- Механика: платные блоки в сценарии: страхование жилья, клининг при переезде, риелторы, проверка контрагента, провайдеры.
- Плюсы: не берёт денег с пользователя; на большой базе даёт доход.
- Минусы: низкий ARPU; разрушает доверие в юридически значимом сценарии; сложность таргетинга; юридические ограничения рекламы.
- Применимость: ограниченно — только уместные партнёрские блоки (страховка аренды) и после масштаба.

**Рекомендация — гибрид «freemium + подписка + разовый пакет»:**
- бесплатно: базовый договор + акт (миссия продукта, рост базы);
- разовый пакет 299–499 ₽: расширенный пакет документов (опись с фото-приложением, памятка сторонам, приоритетная генерация);
- подписка Pro 199 ₽/мес: для С3 (проф. арендодатели, агенты).
- Процент со сделки — этап 2 (после юр. проработки платёжного сопровождения); реклама — только партнёрская и ненавязчиво.
- Обоснование: продукт доверительный и юридический — монетизация не должна стоять между сторонами и документом на массовом сегменте; платят те, у кого потребность повторяется.

## 4.4. Срок окупаемости

**Подход к расчёту:**
- Затраты: CAPEX (MVP: команда 3 мес — 2 разработчика, дизайнер, аналитик/PM; юр. аудит шаблона; стенды) ≈ 1,6 млн ₽. OPEX ≈ 120 тыс. ₽/мес (инфраструктура ~15 тыс., поддержка/доработки ~0,25 FTE ~75 тыс., маркетинг ~30 тыс.).
- Доходы (по модели 4.3): разовый платящий пакет 499 ₽ + подписка 199 ₽/мес.
- Допущения (явные): рамп выхода на плато 6 мес (10% → 100%); команда после MVP — основатели (их зарплаты не в OPEX); цифры спроса — гипотезы для проверки соц. опросом; без учёта налогов.

**Расчёт (выполнен программно, горизонт 24 мес):**

| Сценарий | Плато: платящие сделки/мес | Подписки | Выручка плато, ₽/мес | Месячный CF на плато | Окупаемость |
|---|---|---|---|---|---|
| Пессимистичный | 120 | 40 | 67 840 | −52 160 | не окупается за 24 мес (накопленный дефицит к 22-му мес ≈ −2,93 млн) |
| Базовый | 400 | 150 | 229 450 | +109 450 | ~21 мес |
| Оптимистичный | 1 200 | 500 | 698 300 | +578 300 | ~7 мес |

- Операционная безубыточность: ~240 платящих сделок/мес без подписок; ~181 сделка/мес при 150 подписках.
- Пессимистичный сценарий — сигнал «не масштабировать»: даже при сокращении OPEX до ~45 тыс. (поддержка силами основателей) окупаемость ~70 мес → нужно менять цену/сегмент/затраты.
- Ключевые рычаги: конверсия бесплатных пользователей в платящий пакет и удержание подписчиков (С3).
